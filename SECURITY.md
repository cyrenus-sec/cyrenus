# Security Policy

## Overview

Cyrenus is a kernel-level network security project built using eBPF.  
Security is a core design principle, and we take vulnerability reports seriously.

This document describes how to report security issues and how they are handled.

---

## Supported Versions

Security fixes are provided for:
- The latest released version
- The `main` branch

Users are encouraged to run the most recent release.

---

## Reporting a Vulnerability

**Do not report security vulnerabilities through public GitHub issues.**

To report a vulnerability:

- Email: security@cyrenus.com
- Subject: [SECURITY] Cyrenus Vulnerability Report

Please include:
- A clear description of the issue
- Affected versions or commits
- Steps to reproduce (if available)
- Potential impact assessment
- Any suggested mitigation or patch (optional)

Reports may be submitted anonymously.

---

## Disclosure Process

1. The maintainers will acknowledge receipt within **72 hours**.
2. The issue will be triaged and validated.
3. A fix will be developed privately.
4. A security advisory will be published once a fix is available.
5. CVE assignment will be requested when applicable.

---

## Coordinated Disclosure

We follow a **responsible disclosure** process.  
We request that reporters do not publicly disclose vulnerabilities until a fix and advisory are released.

---

## Security Practices

- All changes are reviewed via pull requests.
- Kernel-level code changes require maintainer review.
- Dependencies are kept minimal and reviewed regularly.
- Security-sensitive logic is documented and tested where possible.

---

## Contact

For security-related matters, contact:
- security@cyrenus.com

For non-security issues, use GitHub Issues or Discussions.
